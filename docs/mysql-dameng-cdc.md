# MySQL 增量迁移与达梦目标

PostgreSQL 系列和达梦目标共用两种启动模式。

- **全量后转增量**：捕获 MySQL 一致快照及位点，完成全量复制后从该位点持续同步。
- **仅增量**：目标表及初始数据已准备完毕，提供 GTID 或 binlog file/position，预检通过后开始同步。

MySQL 需开启 ROW binlog 和 FULL row image。一致快照要求 InnoDB。两类目标均在预检发现 `binlog_transaction_compression=ON` 时阻止启动，并在运行中遇到压缩事务、显式 XA 或部分行镜像时终止本次同步，保留最后成功提交的检查点。已有这类事件的历史 binlog 需要重新建立全量或经核验的增量起点。达梦目标账号需要读取相关目录、写目标表及检查点和显式锁表。全量模式还需要相应建表和对象权限。

## 名称与数据

达梦 schema、表、列统一使用大写，与已有 MySQL → 达梦全量迁移一致。源对象名称保持原样，名称折叠冲突会在预检中报告。源表失败详情仍使用原始名称。

TIMESTAMP 在源库会话时区下转换，包含历史夏令时和微秒，保证应用机器时区变化不会改变结果；DATETIME 保持源壁钟值。

数据按源事务顺序应用，源事务中的所有目标写入与检查点在同一个达梦事务提交。恢复以目标检查点为准。主键和双端确认的非空唯一键用于定位；没有可靠键时以更新前完整行匹配，通过 ROWID 每次仅更新或删除一条重复行。变长字符串会精确区分尾随空格及大小写；CHAR/NCHAR 按固定宽度补空格规则匹配。无法找到旧行时暂停为行冲突，检查点不前进。

ENUM/SET 序号、无符号整数和字段字符集先转换为与全量读取一致的值。日期、微秒、Decimal、文本和二进制沿用现有达梦转换规则；零日期按现有规则替换为 `1900-01-01`。CLOB/BLOB 使用完整 LOB 比较，不截断为短字符串。目标列容量仍遵循既有类型映射：例如源 BIGINT UNSIGNED 超出目标 BIGINT 范围时应修正目标类型，增量转换不会把它写成负数。

BIT 在全量和增量阶段共用无符号转换，BIT(64) 高位值不会溢出为负数。默认 BIT → NUMBER(1) 映射无法容纳的值会明确报错；已将目标列扩容为 NUMBER(20) 时可完整承接 64 位值。

JSON 行值会按 MySQL 的 SQL 输出格式统一空格、键顺序和数字表示，保证全量后的无键行仍可定位。支持普通 JSON 值及 MySQL binary JSON 中的 DECIMAL、DATE、DATETIME、TIMESTAMP、TIME 扩展值；DECIMAL 保留最高 65 位精度和小数末尾零，不经过浮点数转换，时间扩展保持源 JSON 文本（包含微秒、零日期和历史非法日期）。`PARTIAL_JSON` 部分更新、未知 opaque 扩展或超出可精确还原范围的值会明确报错并保留检查点。遇到这些错误需关闭部分更新或整理不支持的扩展值，再重新建立全量起点；修改当前数据不会改写已经产生的 binlog。

## 结构快照与升级

两类目标的检查点都保存有序列名、类型定义、字符集、主键、自增信息、唯一键与结构摘要。应用库通过 `source_schema_version` 记录镜像版本。恢复以目标检查点中的结构和位点为准。

全量模式在一致快照的全局读锁内捕获结构，并对所选表（含空表）取得持续到快照结束的元数据锁。表清单固定；复制期间源 DDL 会等待，普通 DML 在释放初始化全局锁后可以继续。仅增量模式读取当前结构和边界，然后只读扫描起点至边界的 binlog；发现可能影响源库的 DDL、缺失日志、事务中间位点或无法确认结构关系时拒绝起点。DDL 识别采取保守规则，同源库但未选中的表发生 DDL 也可能要求重建。

升级时，缺少当前结构快照的未终止 PostgreSQL 系列任务标记为不可恢复并释放占用，历史报告、目标数据及旧检查点继续保留。可显式新建全量快照任务，或用已核对的目标基线及其位点新建仅增量任务。已有冻结结构的达梦任务从目标库检查点恢复。

## 暂停、恢复与切换

- 源 DDL 会暂停任务，不自动转换 DDL。人工适配目标结构后确认时，先验证目标兼容性，再核验阻塞 DDL 之后没有其他可能影响范围的 DDL；连续多次 DDL 导致结构无法对应时拒绝确认，要求重建起点。结构快照与新位点在同一目标事务保存。
- DDL 确认与启动、恢复、放弃共享生命周期互斥锁，Runner 退出后才允许确认；目标检查点行锁校验旧位点和结构摘要，禁止并发请求回退检查点。若目标已提交而应用状态保存失败，保留阻塞信息，重试确认会根据目标的持久确认标记修复状态；两端保存成功后才启动 Runner。
- 目标不得启用业务触发器，因为源触发器副作用已经包含在 ROW binlog。支持 `TRIG_DML_LOCK` 的达梦实例要求其为 `0`，使用 ROW EXCLUSIVE 表锁保护检查与写入；较旧版本没有该参数时使用 EXCLUSIVE 表锁，目标写入及 DDL 会等待事务结束。参数查询失败或值非零均明确阻止同步。
- 任务恢复要求可信的目标检查点。相同物理目标 Schema 只允许一个未终止的增量任务占用，暂停、失败和服务重启期间仍保留占用。
- PG 和达梦的普通定位键变更按旧键原地更新。PG 核对受影响的外键行为。涉及达梦 `IDENTITY` 的替换只在持锁确认没有入向外键时执行。无法安全应用的外键操作会回滚并保留检查点。
- 文件位点会在实际读取到安全的 binlog 轮转元数据后推进，即使轮转之后没有新的业务事务。

### 最终校验

准备切换后，源 MySQL 实例和目标库需保持停写。系统追到固定边界，按目标检查点中的有效表清单核对行数，并执行完整内容比较。有主键的表比较主键和内容，无主键表比较整行和重复次数。任务详情的「最终校验」展示每张表的结果。

内容存在差异或无法完成校验时，任务进入「带风险待确认」。完成切换需要单独确认内容豁免，API 请求传入 `acknowledge_content_validation: true`。任务保留原始每表结果，并记录确认人和时间。行数一致、目标检查点到达切换边界、源库位点复核和自增校正均须通过。历史任务仅有行数报告时，需要重新准备切换并运行内容校验。

PG 序列按 MySQL 自增下一值、目标最大值加一和目标序列当前下一值中的最大值向前校正。自增校正无法安全完成时阻止切换。

当自增当前值等于初始种子、且现有数据无法证明首值已消费时，按种子作为保守下界校验，并明确提示无法确认的情况；不会通过插入测试行消耗自增值。下一值可能超过 INT/BIGINT 范围时同样阻止切换。

全量单表失败后其余表继续迁移，失败表不进入增量范围。达梦 DDL 隐式提交，因此审阅记录先冻结待清理对象的身份及进度，再执行可重试清理，全部成功后才标记初始化完成。重试不会重跑全量、重置已推进位点或认领同名替换对象。建表失败遗留的原有对象不会在审阅确认时被删除。

## 事务内查询与 SQL 复用

启动预检仍检查完整目标 schema。应用事务先锁定涉及表，再按每批最多 128 张表查询列、索引和触发器；只处理少量表的事务不再扫描整个 schema。每表的行写入描述在事务内复用，以完整 SQL 为键缓存最多 256 条预编译写入语句，超过上限直接执行，结束或回滚时统一释放。源事务顺序、upsert、IDENTITY 清理、LOB 比较及触发器互斥保持原语义。

运行中的增量事务在内存中缓冲。切换时的内容校验使用有界内存和临时摘要文件。

## 验证

使用独立 MySQL 和达梦测试实例。测试创建唯一源数据库和目标 schema，完成后自行清理；测试达梦管理员需有创建 schema 的权限。

实库测试期间需独占 MySQL 实例，其他写入测试必须串行运行。不同数据库仍共享实例级 binlog，其他测试的写入会推进切换边界，使完成切换返回 409。下面使用 `-p 1` 串行执行测试包；也不要同时在其他进程中运行写入该 MySQL 实例的测试。

```bash
export CDC_DAMENG_INTEGRATION=1
export CDC_MYSQL_DSN='root:password@tcp(127.0.0.1:13309)/?parseTime=true'
export CDC_DAMENG_DSN='dm://SYSDBA:password@127.0.0.1:15239'
export DBGOLD_CDC_MYSQL_DSN="$CDC_MYSQL_DSN"

go test -p 1 -tags=integration ./datamigrate/cdc ./api/handler \
  -run 'Test(Dameng|ConvertDameng|IncrementalDameng)' -count=1 -timeout=8m
```

覆盖两种启动模式、GTID/file 位点、真实 binlog 值转换、回滚、跨表自增事务、NULL/空值、1 MB LOB、无键重复行、暂停恢复、DDL 确认、切换、清理中断及对象替换。触发器并发测试验证 CREATE/ENABLE/DISABLE 在目标事务持锁期间等待。新增用例覆盖暂停后先 UPDATE 再交换同类型列顺序、增删列、连续 DDL 拒绝、历史起点拒绝、重复确认与放弃并发、目标提交后应用状态写入故障及重试、压缩/XA 阻断、空表元数据锁和固定快照表清单。

已在 MySQL 8.0.36、DM8 `20240920` 与 `20261008` 镜像上验证核心写入和触发器互斥；PostgreSQL 的原有 CDC 集成测试仍作为回归保留。

本轮回归使用隔离的 MySQL 8.0.36 与 DM8 `20261008`（`COMPATIBLE_MODE=4`）。目录查询范围的单元测试覆盖 100、1000、3000 张表场景及 128 表分批边界，预编译测试覆盖复用、256 条上限和资源关闭；这些是行为验证，不代表吞吐量基准。

并发回归同时修复了内置达梦驱动的两处竞争：取消请求时仅关闭底层连接，中止 I/O 并由服务端回滚，避免取消协程与执行协程同时清理语句；连接握手的 DH 参数改为每个密钥对象独立持有，避免并发连接改写共享参数。
