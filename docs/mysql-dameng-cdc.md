# MySQL → 达梦增量迁移

增量面板支持达梦目标，复用现有两种启动模式：

- **全量后转增量**：捕获 MySQL 一致快照及位点，完成全量复制后从该位点持续同步。
- **仅增量**：目标表及初始数据已准备完毕，提供 GTID 或 binlog file/position，预检通过后开始同步。

MySQL 需开启 ROW binlog、FULL row image；一致快照要求 InnoDB。账号权限、binlog 保留时间、缺失目标表排除和失败表审阅沿用现有流程。达梦目标账号需要读取相关目录、写目标表及检查点、显式锁表；全量模式还需要相应建表和对象权限。

## 名称与数据

达梦 schema、表、列统一使用大写，与已有 MySQL → 达梦全量迁移一致。源对象名称保持原样，名称折叠冲突会在预检中报告。源表失败详情仍使用原始名称。

TIMESTAMP 在源库会话时区下转换，包含历史夏令时和微秒，保证应用机器时区变化不会改变结果；DATETIME 保持源壁钟值。

数据按源事务顺序应用，源事务中的所有目标写入与检查点在同一个达梦事务提交。恢复以目标检查点为准。主键和双端确认的非空唯一键用于定位；没有可靠键时以更新前完整行匹配，通过 ROWID 每次仅更新或删除一条重复行。变长字符串会精确区分尾随空格及大小写；CHAR/NCHAR 按固定宽度补空格规则匹配。无法找到旧行时暂停为行冲突，检查点不前进。

ENUM/SET 序号、无符号整数和字段字符集先转换为与全量读取一致的值。日期、微秒、Decimal、文本和二进制沿用现有达梦转换规则；零日期按现有规则替换为 `1900-01-01`。CLOB/BLOB 使用完整 LOB 比较，不截断为短字符串。目标列容量仍遵循既有类型映射：例如源 BIGINT UNSIGNED 超出目标 BIGINT 范围时应修正目标类型，增量转换不会把它写成负数。

BIT 在全量和增量阶段共用无符号转换，BIT(64) 高位值不会溢出为负数。默认 BIT → NUMBER(1) 映射无法容纳的值会明确报错；已将目标列扩容为 NUMBER(20) 时可完整承接 64 位值。

JSON 行值会按 MySQL 的 SQL 输出格式统一空格、键顺序和数字表示，保证全量后的无键行仍可定位。支持普通 JSON 值及 MySQL binary JSON 中的 DECIMAL、DATE、DATETIME、TIMESTAMP、TIME 扩展值；DECIMAL 保留最高 65 位精度和小数末尾零，不经过浮点数转换，时间扩展保持源 JSON 文本（包含微秒、零日期和历史非法日期）。`PARTIAL_JSON` 部分更新、未知 opaque 扩展或超出可精确还原范围的值会明确报错并保留检查点。遇到这些错误需关闭部分更新或整理不支持的扩展值，再重新建立全量起点；修改当前数据不会改写已经产生的 binlog。

## 暂停、恢复与切换

- 源 DDL 仍会暂停任务。人工处理目标结构后点击确认，重新加载元数据再恢复；不自动转换 DDL。
- 目标不得启用业务触发器，因为源触发器副作用已经包含在 ROW binlog。支持 `TRIG_DML_LOCK` 的达梦实例要求其为 `0`，使用 ROW EXCLUSIVE 表锁保护检查与写入；较旧版本没有该参数时使用 EXCLUSIVE 表锁，目标写入及 DDL 会等待事务结束。参数查询失败或值非零均明确阻止同步。
- 每笔事务通过同一连接切换和清理 `IDENTITY_INSERT`。自增列值变化采用同事务删旧插新；普通更新不直接修改自增列。
- 切换前追到固定边界，检查行数及自增下一值。自增水位不能覆盖已导入数据或源下一值时阻止完成切换，要求单独修复；不会自动 DROP/ADD 自增属性。

当自增当前值等于初始种子、且现有数据无法证明首值已消费时，按种子作为保守下界校验，并明确提示无法确认的情况；不会通过插入测试行消耗自增值。下一值可能超过 INT/BIGINT 范围时同样阻止切换。

全量单表失败后其余表继续迁移，失败表不进入增量范围。达梦 DDL 隐式提交，因此审阅记录先冻结待清理对象的身份及进度，再执行可重试清理，全部成功后才标记初始化完成。重试不会重跑全量、重置已推进位点或认领同名替换对象。建表失败遗留的原有对象不会在审阅确认时被删除。

## 验证

使用独立 MySQL 和达梦测试实例。测试创建唯一源数据库和目标 schema，完成后自行清理；测试达梦管理员需有创建 schema 的权限。

实库测试期间需独占 MySQL 实例，其他写入测试必须串行运行。不同数据库仍共享实例级 binlog，其他测试的写入会推进切换边界，使完成切换返回 409。下面使用 `-p 1` 串行执行测试包；也不要同时在其他进程中运行写入该 MySQL 实例的测试。

```bash
export CDC_DAMENG_INTEGRATION=1
export CDC_MYSQL_DSN='root:password@tcp(127.0.0.1:13309)/?parseTime=true'
export CDC_DAMENG_DSN='dm://SYSDBA:password@127.0.0.1:15239'
export DBGOLD_CDC_MYSQL_DSN="$CDC_MYSQL_DSN"

go test -p 1 -tags=integration ./datamigrate/cdc ./api/handler \
  -run 'Test(Dameng|ConvertDameng|IncrementalDameng)' -count=1 -timeout=5m
```

覆盖两种启动模式、GTID/file 位点、真实 binlog 值转换、回滚、跨表自增事务、NULL/空值、1 MB LOB、无键重复行、暂停恢复、DDL 确认、切换、清理中断及对象替换。触发器并发测试验证 CREATE/ENABLE/DISABLE 在目标事务持锁期间等待。

已在 MySQL 8.0.36、DM8 `20240920` 与 `20261008` 镜像上验证核心写入和触发器互斥；PostgreSQL 的原有 CDC 集成测试仍作为回归保留。
